description: Install Spool, load and match sample rows, watch each company keep its ID as more rows arrive, and extract records from a call note, from the CLI, over HTTP and over MCP.
---

In five minutes you'll install Spool, load and match a CRM export, watch each company keep its ID as more rows arrive, and pull three more records out of a call note. Each step shows the CLI command, then the same step over HTTP and as an MCP tool call. Run the commands. The other two are for reference.

## Requirements

- Linux (x86-64 or arm64, glibc 2.34+) or macOS on Apple silicon.
- `curl` and `tar`.
- [`uv`](https://docs.astral.sh/uv/) for the extraction step, which runs the sample extractor. Every other step works without it.

## Install

{/* sample: new session; skip installs the release, and the samples run the binary they are given */}

```sh
curl -fsSL https://github.com/alexpatow/spool/releases/latest/download/install.sh | sh
```

The script downloads the build for your platform, verifies its checksum, unpacks it to `~/.local/share/spool/0.2.0` and symlinks `~/.local/bin/spool`. It also links the man pages and the bash, zsh and fish completions under `~/.local/share`. It doesn't need root or touch your shell config. If `~/.local/bin` isn't on your `PATH`, it prints the line to add.

To install by hand, unpack `spool-0.2.0-<target>.tar.gz` from the [release](https://github.com/alexpatow/spool/releases/tag/v0.2.0) and put its `bin/` on your `PATH`. Keep `bin/` and `lib/` side by side, because the binary loads DuckDB from `../lib`.

```sh
spool --version
```

```text title="Output"
spool 0.2.0
```

## Create a project

```sh
spool init companies --example companies
cd companies
```

```text title="Output"

  sources/crm.yaml                   the columns of a CRM export
  sources/notes.yaml                 what a record found in a note may say
  entities/company/entity.yaml       what companies are compared by
  entities/company/rules/            three rules, one line of SQL each
  transforms/name_key.sql            the lower-case name the rules compare
  extractors/companies.py            finds company names in text, with a small model
  samples/crm-1.csv                  six rows to load first
  samples/crm-2.csv                  three more for later
  samples/notes-1.txt                a call note that names three companies
  .gitignore                         keeps the server's data, .spool/, and .env out of Git
  .env.example                       the form of .env, where your code's secrets go
  AGENTS.md                          what a coding agent should know here; CLAUDE.md imports it
  .agents/skills/                    skills that teach coding agents Spool, linked from .claude/skills/

  cd companies
  spool dev                          runs the server on this machine
  spool load samples/crm-1.csv       loads the first rows, from a second terminal
  spool extract samples/notes-1.txt  finds the companies in the note

The extractor is a Python file, which Spool runs with `uv`. Its first run fetches
about 330 MB, most of it the model, and later runs fetch nothing.
```

A project is a directory you keep in Git. `--example companies` fills it with the sample used on this page. Leave it off to get an empty project for your own data. The sample declares a source of rows, `crm`, a source of documents, `notes`, and one **entity type**, `company`. An entity type is a kind of thing you want one ID for. The first rows:

```csv title="samples/crm-1.csv"
c-2,ACORN TOOLS,GB
c-3,Acorn Tools Ltd,GB
c-4,Larkfield Logistics,GB
c-5,Halden Group,GB
```

## Start the server

{/* sample: background */}

```sh
spool dev
```

```text title="Output"
project   .
store     ./.spool/dev.duckdb
applied   b6dff33d6c0977f4afb2497792bcaa9785e8b865994fa5c94eb9761f57a6e0a7 (declared company)
accounts  ./.spool/dev.auth.sqlite
listening on http://127.0.0.1:7765
studio    http://127.0.0.1:7765/
mcp       http://127.0.0.1:7765/mcp
```

`spool dev` listens on localhost with no sign-in, keeps its data in `.spool/dev.duckdb`, and reloads project files as you save them. The last two lines are the studio, Spool's web UI, and the MCP endpoint for agents. Leave it running and open a second terminal in `companies`.

If port 7765 is taken, start it with `--listen 127.0.0.1:7766`, set `SPOOL_URL=http://127.0.0.1:7766` in the second terminal, and use that address in the HTTP calls. One server runs on a store at a time, so a second `spool dev` on the same project is refused.

## Load rows

```sh
spool load samples/crm-1.csv
```

```text title="Output"
loaded  6 rows into source `crm`, type `company`: 6 new
next: `spool match` places them in identities
```

Each row is now a **record**. Loading doesn't match, and loading the same file again adds nothing.

Over HTTP:

{/* sample: after */}

```sh
curl -s -X POST 'http://127.0.0.1:7765/v1/load?source=crm&entity_type=company' -H 'content-type: text/csv' --data-binary @samples/crm-1.csv
```

As an MCP tool call, with one object per row:

{/* sample: after */}

```json title="MCP tool call"
{ "name": "load_rows", "arguments": { "source": "crm", "entity_type": "company",
  "rows": [ { "id": "c-1", "name": "Acorn Tools", "country": "GB" } ] } }
```

## Match

```sh
spool match
```

```text title="Output"
run         2, type `company`
examined    6 records, 4 candidate pairs
judgements  3 match, 1 no_match
placed      6 records, 4 identities created
```

A match compares new records with each other and with everything already placed, and puts each one in an identity. Four pairs were worth comparing: three were judged the same company, and one wasn't.

Over HTTP, where a match is a run:

```sh
curl -s -X POST http://127.0.0.1:7765/v1/match -d '{"entity_type": "company"}'
```

As an MCP tool call:

```json title="MCP tool call"
{ "name": "run_match", "arguments": { "entity_type": "company" } }
```

An **identity** is one company: an ID and the records that belong to it. The three spellings of Acorn Tools share one. That ID, in the last column, is what other systems store. ```

As an MCP tool call:


The two Halden Groups share a name but not a country. The rule that kept them apart is one line:

{/* sample: existing */}

```sql title="entities/company/rules/no_match/different_country.sql"
-- A no_match rule says a pair is not the same thing, and wins over any
-- match rule. This one holds only when both rows have a country.
l.country <> r.country
```

The rule that matched "Acorn Tools Ltd" to "Acorn Tools" is one line too:

{/* sample: existing */}

```sql title="entities/company/rules/match/similar_name.sql"
-- A match rule says a pair is the same thing: here, two names that are
-- close. The similarity is 1 for equal names and 0 for names with nothing
-- in common.
jaro_winkler_similarity(l.name_key, r.name_key) >= 0.92
```

A rule is a SQL condition over two records, `l` and `r`. [Matching](/docs/concepts/matching) covers the three kinds.

```sh

```

As an MCP tool call:

```json title="MCP tool call"

```

## Extract records from text

Records can also come from text. An **extractor** reads a document and reports where it names a company, and each place becomes a record. The project includes a sample document and extractor.

{/* sample: existing */}

```text title="samples/notes-1.txt"
Call with Dana Reyes on 12 November. She has moved to Acorn Tools Ltd and runs
purchasing there. They now ship through Larkfield Logistics Ltd, and she asked
whether we work with Brightwater Foods Ltd, their new supplier.
```

{/* sample: existing */}

```python title="extractors/companies.py"
# /// script
# requires-python = ">=3.10,<3.13"
# dependencies = ["fast-gliner>=0.4.1,<0.5"]
# ///
"""Finds the companies a document names, with a small model that runs here.

An extractor reads documents and says where they name something, and each
thing it finds becomes a record. Spool runs this file with `uv`, which
installs what the lines above list. The first run fetches about 330 MB, most
of it the model, and later runs fetch nothing. No document leaves this
machine and there is no key to set.
"""

import sys

from fast_gliner import FastGLiNER
from spool import extractor

# What to look for. On the left is the word the model is given, and the word
# decides what is found: "company" misses most universities, parties and
# charities, and "organization" finds them. Any word will do, "person" or
# "medicine" as well. On the right is the entity type of this project that
# such a find becomes a record of.
LOOK_FOR = {"company": "company"}

# GLiNER small: 245 MB, Apache-2.0, at the version it was tried with.
MODEL = "onnx-community/gliner_small-v2.1"
WEIGHTS = "onnx/model_q4f16.onnx"
VERSION = "8142fb00740ccea973e64b1272949ff48653df5e"


def load():
    """The model: read from this machine if it is here, and fetched if not."""
    files = {"onnx_path": WEIGHTS, "allow_patterns": ["*.json", WEIGHTS], "revision": VERSION}
    try:
        return FastGLiNER.from_pretrained(MODEL, local_files_only=True, **files)
    except FileNotFoundError:
        print(f"Fetching the model {MODEL} (245 MB), once.", file=sys.stderr)
        return FastGLiNER.from_pretrained(MODEL, **files)


# Loaded as the file starts, so that `spool build --install` fetches it too.
model = load()


@extractor
def find(document):
    # The model reads 384 words at a time and ignores the rest, so a long
    # document is read in pieces.
    for piece in document.pieces(300):
        for found in model.predict_entities(piece.text, list(LOOK_FOR)):
            # The model counts in bytes, and Spool in characters.
            start = len(piece.text.encode()[: found["start"]].decode())
            end = start + len(found["text"])
            # `name` is a column of sources/notes.yaml.
            yield piece.mention(LOOK_FOR[found["label"]], start, end, name=found["text"])
```

Spool runs it with `uv`. It asks a small local model where the text names a company, and the matched text becomes the record's `name`. There's no API key, and nothing leaves your machine.

```sh
spool extract samples/notes-1.txt
```

```text title="Output"

loaded     1 new, 0 already held, 0 new versions

  company  Larkfield Logistics Ltd  notes:notes-1.txt[119-142]
  company  Brightwater Foods Ltd    notes:notes-1.txt[179-200]

```

Three records came out of the note, each with its document and character range. They're records like the rows, so the same rules match them.

Over HTTP, it's two calls: store the document, then run the extractor.

```sh
curl -s -X POST 'http://127.0.0.1:7765/v1/documents?source=notes&key=notes-1.txt' -H 'content-type: text/plain' --data-binary @samples/notes-1.txt
```

```sh
curl -s -X POST http://127.0.0.1:7765/v1/extractions -d '{}'
```

As MCP tool calls:

```json title="MCP tool call"
{ "name": "load_documents", "arguments": { "source": "notes",
  "documents": [ { "key": "notes-1.txt", "text": "Call with Dana Reyes on 12 November. ..." } ] } }
```

```json title="MCP tool call"
{ "name": "run_extraction", "arguments": { "extractor": "companies" } }
```

`LOOK_FOR` in the file tells the model to look for "company". Change the word and it finds other things. Extractors are Python or TypeScript files in `extractors/`, run with `uv` or `bun`. [Extraction](/docs/concepts/extraction) walks through writing one.

## Connect an agent

The server speaks the Model Context Protocol (MCP) at the `mcp` address it printed, and `spool dev` needs no token. For Claude Code:

{/* sample: not built agent-run */}

```sh
claude mcp add --transport http spool http://127.0.0.1:7765/mcp
```

For Codex:

{/* sample: not built agent-run */}

```sh
codex mcp add spool --url http://127.0.0.1:7765/mcp
```

Then try: "Load samples/crm-2.csv into Spool, match it, and tell me why c-5 and c-6 are different companies." It'll use `load_rows`, `run_match`, `search_records` and `explain_pair`, plus `load_documents` and `run_extraction` for text. [MCP](/docs/mcp) lists every tool.

Open a coding agent in the project to write an extractor or a rule, and it picks up the `AGENTS.md` and skills that `spool init` wrote. [Coding agents](/docs/agents) lists them.

## Stop

Ctrl-C in the first terminal stops the server. Data stays in `.spool/dev.duckdb`. Delete `.spool/` to start over.
