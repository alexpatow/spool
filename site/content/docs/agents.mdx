---
title: Coding agents
description: The skills and AGENTS.md that spool init writes into every project, so Claude Code, Codex, Cursor and other coding agents can write extractors and rules and run Spool, and how spool update-skills keeps them current.
---

A coding agent that hasn't seen Spool will guess, based on other tools' docs. So `spool init` writes what agents read into every project: an `AGENTS.md` with what to know about any Spool project, and skills, short files that each teach one task with the exact commands and file formats of your `spool` version.

{/* sample: new session */}

```sh
spool init companies --example companies
cd companies
```

## What's written

| File | What it holds | Read by |
| --- | --- | --- |
| `AGENTS.md` | What to know about a Spool project, and a list of the skills | Codex, Cursor, and Claude Code when there's no `CLAUDE.md` |
| `CLAUDE.md` | One line, `@AGENTS.md`, which imports it | Claude Code |
| `.agents/skills/<skill>/SKILL.md` | One skill each | Codex, Cursor, and other agents that support the [Agent Skills](https://agentskills.io) format |
| `.claude/skills/<skill>` | A symlink to the skill's folder in `.agents/skills/` | Claude Code |

`.claude/skills/` holds symlinks rather than copies, so there's one file to edit, and Cursor, which reads both folders, lists each skill once. Commit them all with the project. Git stores symlinks as symlinks on Linux and macOS.

Agents read only each skill's name and description until a task needs it, then load the full file. The five skills:

| Skill | For |
| --- | --- |
| `spool-project` | Sources, entity types, features and transforms, checked with `spool info` |
| `spool-rules` | Block, match and no_match rules, `spool explain`, and previewing rule changes with `spool match --rematch` and `spool recompute` |
| `spool-extractor` | Extractors in Python or TypeScript, with a local or hosted model, run with `spool extract` |
| `spool-data` | `spool dev`, `spool load`, `spool match`, `spool show`, `spool explain`, `spool retract`, and their JSON output |
| `spool-api` | The HTTP API and MCP, correcting identities with changesets, and deploying with `spool build`, `spool apply`, `spool serve` and `spool token` |

The source is in [`crates/spool-cli/assets/agents`](https://github.com/alexpatow/spool/tree/main/crates/spool-cli/assets/agents), and the binary embeds them.

## Use them

Open the project in your agent and ask for what you want, as you would a colleague who's read the skills:

```text
Write an extractor that finds the people and companies in the call notes in
notes/, using the OpenAI API, and show me what it finds in the first three.
```

```text
Why are crm:c-5 and crm:c-6 not one company? Change the rules so that a
leading "The" does not matter, and show me what that changes before applying.
```

Agents can also reach the running server over [MCP](/docs/mcp), and the skills say when to use which. `AGENTS.md` tells agents to ask before starting `spool dev`, never to reset the store to get a better match, and never to print `.env`.

## Keep them current

Skills match the `spool` version that wrote them. After installing a new release, update them:

```sh
spool update-skills
```

```text title="Output"
project  .

  unchanged  AGENTS.md
  unchanged  CLAUDE.md
  unchanged  .agents/skills/spool-project/SKILL.md
  unchanged  .claude/skills/spool-project
  unchanged  .agents/skills/spool-rules/SKILL.md
  unchanged  .claude/skills/spool-rules
  unchanged  .agents/skills/spool-extractor/SKILL.md
  unchanged  .claude/skills/spool-extractor
  unchanged  .agents/skills/spool-data/SKILL.md
  unchanged  .claude/skills/spool-data
  unchanged  .agents/skills/spool-api/SKILL.md
  unchanged  .claude/skills/spool-api

The files for agents are this version's already.
```

`spool update-skills` also adds them to projects created before `spool init` wrote them.

Edit them freely. Each skill carries its own hash as `spool-sha256` under `metadata` in its frontmatter, and so does the first marker line of Spool's section of `AGENTS.md`. If the hash matches the content, the file is as Spool wrote it and `spool update-skills` replaces it. Edited files are kept and listed as `kept`, and `spool update-skills --force` replaces them too.

- Put your own notes in `AGENTS.md` above or below Spool's section, which runs from `<!-- spool:begin` to `<!-- spool:end -->`. The rest of the file is never touched, and an existing `AGENTS.md` gets Spool's section appended.
- An existing `CLAUDE.md` is kept. Add `@AGENTS.md` to it so Claude Code reads `AGENTS.md`.
- Name your own skills without the `spool-` prefix. Unedited `spool-` skills that this version doesn't ship are removed.
