`spool` is one binary. Three commands run a server. The rest work on a project directory or call a running server over HTTP. `spool <command> -h` lists a command's options, and `spool <command> --help` gives the full description. The [command reference](/docs/cli-reference) lists every option, generated from the binary's help. After install, `man spool` says the same.

| Command | What it does | Works on |
| --- | --- | --- |
| [`spool init`](#spool-init) | Creates a project, empty or from an example | A directory |
| [`spool info`](#spool-info) | Lists what a project declares and checks its SQL | A directory |
| [`spool dev`](#spool-dev) | Runs a local server that reloads project files as you save | A directory |
| [`spool reset`](#spool-reset) | Empties the development store of `spool dev` | A directory |
| [`spool update`](#spool-update) | Installs the latest stable Spool release and refreshes project skills | A Spool installation |
| [`spool update-skills`](#spool-update-skills) | Updates a project's coding-agent skills to this version's | A directory |
| [`spool load`](#spool-load) | Loads a file of rows | A running server |
| [`spool extract`](#spool-extract) | Stores text files as documents and runs an extractor | A running server |
| [`spool match`](#spool-match) | Matches new records of every entity type | A running server |
| [`spool show`](#spool-show) | Shows runs, records and their attributes, identities, documents, review items, drafts and the log | A running server |
| [`spool explain`](#spool-explain) | Says why two records share an identity or don't, and what holds an identity together | A running server |
| [`spool retract`](#spool-retract) | Retracts rows a source no longer holds | A running server |
| [`spool build`](#spool-build) | Checks a project and compiles it into a manifest | A directory |
| [`spool apply`](#spool-apply) | Applies a manifest to a store | A store file |
| [`spool serve`](#spool-serve) | Runs the server from a manifest and a store | A store file |
| [`spool token`](#spool-token) | Creates, lists and revokes tokens | A store file |
| [`spool schema`](#spool-schema) | Prints the JSON Schema of the API | Nothing |
| [`spool bench`](#spool-bench) | Runs a benchmark scenario | A directory |
| [`spool completions`](#spool-completions) | Prints a shell completion script | Nothing |

Commands that call a server take `--url` (default `$SPOOL_URL`, or `http://127.0.0.1:7765`) and `--token` (default `$SPOOL_TOKEN`; `spool dev` needs none).

Merging, splitting, undoing, review decisions and draft approval go through [the HTTP API](/docs/api), the studio or [MCP](/docs/mcp).

## Output

Every command that prints a result takes `-o, --output <format>`, and `--json` as shorthand for `-o json`. The format is the same on a terminal and in a pipe.

| Format | What it prints |
| --- | --- |
| `table` | For people. The default. Columns can change between releases, so don't parse it in scripts |
| `json` | One JSON document: the server's response, described by [`spool schema`](#spool-schema), or a local command's report |
| `ndjson` | One list item per line, for `jq` and other streaming tools. Anything else is its JSON on one line |
| `csv` | A list's columns, with full IDs and untruncated values. Commands that print a report, such as `spool match` or `spool show runs <run>`, reject `csv` up front |

Standard output carries the result only. Hints, notes, next steps and progress go to standard error. Progress is a spinner or bar for `spool load`, `spool extract`, `spool match`, `spool recompute` and `spool retract`, drawn on a terminal only. `-q` silences all of it, so `spool show identities -o csv > identities.csv` writes only rows. `spool serve`, `spool dev` and `spool schema` take no `-o`: the first two run a server, and `spool schema` always prints JSON.

Tables, hints and errors are coloured on a terminal. `--color never` turns colour off and `--color always` keeps it in a pipe. Without the flag, `NO_COLOR` and `CLICOLOR_FORCE` do the same. JSON, NDJSON and CSV are never coloured.

Failures print `error:`, followed by a `hint:` line when there's a fix. Bad arguments print usage and exit 2. Other failures exit 1, and Ctrl-C exits 130.

## spool init

`spool init [<dir>] [--example <name>]`

Creates a project in `<dir>`, or in the current directory. An empty project has `sources/`, `entities/`, `transforms/` and `extractors/` (each with a `.gitkeep`), a `.gitignore` covering `.spool/` and `.env`, and a `.env.example`. `spool dev` runs on it as is. It also writes the files coding agents read, covered in [Coding agents](/docs/agents): `AGENTS.md`, a `CLAUDE.md` that imports it, and skills in `.agents/skills/`, each symlinked from `.claude/skills/`.

`spool init` uses Git from `PATH` to initialize a repository with no commits. It keeps an existing repository. The folder must be empty apart from `.git` and `.DS_Store`. Otherwise `spool init` lists a few of the files and writes nothing.

`--example companies` writes a complete project instead: a row source, `crm`, a document source, `notes`, a `company` entity type with features, a transform, three rules and an extractor, plus two CSV files and a call note under `samples/`. An unknown example name is refused with the list of examples.

{/* sample: new session */}

```sh
spool init companies --example companies
cd companies
```

```text title="Output"
created   companies

  sources/crm.yaml                   the columns of a CRM export
  sources/notes.yaml                 what a record found in a note may say
  entities/company/entity.yaml       what companies are compared by
  entities/company/rules/            three rules, one line of SQL each
  transforms/name_key.sql            the lower-case name the rules compare
  extractors/companies.py            finds company names in text, with a small model
  samples/crm-1.csv                  six rows to load first
  samples/crm-2.csv                  three more for later
  samples/notes-1.txt                a call note that names three companies
  .gitignore                         keeps the server's data, .spool/, and .env out of Git
  .env.example                       the form of .env, where your code's secrets go
  AGENTS.md                          what a coding agent should know here; CLAUDE.md imports it
  .agents/skills/                    skills that teach coding agents Spool, linked from .claude/skills/

  cd companies
  spool dev                          runs the server on this machine
  spool load samples/crm-1.csv       loads the first rows, from a second terminal
  spool extract samples/notes-1.txt  finds the companies in the note

The extractor is a Python file, which Spool runs with `uv`. Its first run fetches
about 330 MB, most of it the model, and later runs fetch nothing.
```

Without `--example`:

```sh
spool init ../my-data
```

```text title="Output"
created   ../my-data

  sources/             a YAML file for each source of rows or documents
  entities/            a folder for each entity type, with its features and its rules
  transforms/          SQL functions that features are made with
  extractors/          Python or TypeScript files that find records in text
  .gitignore           keeps the server's data, .spool/, and .env out of Git
  .env.example         the form of .env, where your code's secrets go

  .agents/skills/      skills that teach coding agents Spool, linked from .claude/skills/

  cd ../my-data
  spool dev            runs the server, and applies each file as you save it

The project is empty. Declare a source under sources/ and an entity type
under entities/, then load your rows with `spool load`. To see a project that
works first, with sample rows: spool init companies --example companies
```

In a folder that has files, it lists a few, suggests `spool init <name>` for a new folder, and writes nothing. Inside a project, it says so:

{/* sample: fails */}

```sh
spool init
```

```text title="Output"
error: this folder is a project already: it has an entities/ folder
```

The project's `.env` sets environment variables for its extractors and strategies, such as a hosted model's API key. Spool rereads it each time it starts one and never prints a value. Variables already set in Spool's environment win. Each line is `NAME=value`, optionally prefixed with `export ` and optionally quoted. Lines starting with `#` are comments.

## spool info

`spool info [<dir>]`

Lists the project's sources (with each column and the features it becomes), entity types (with features, rules and strategies) and extractors. It checks every SQL file and needs no server. To see what records actually hold, use [`spool show attributes`](#spool-show).

```sh
spool info
```

## spool dev

`spool dev [<dir>] [--listen <addr>] [--store <path>] [--task-timeout <s>] [--tasks <dir>]`

Runs a server straight from a project directory, with data in `.spool/dev.duckdb`. Project files are applied as you save them. A change that doesn't compile is reported, and the last good version keeps running.

It listens on `127.0.0.1:7765` only. There's no sign-in and no token: every change is recorded under one admin account. Use `spool serve` for a server other people reach.

{/* sample: background */}

```sh
spool dev
```

```text title="Output"
project   .
store     ./.spool/dev.duckdb
applied   b6dff33d6c0977f4afb2497792bcaa9785e8b865994fa5c94eb9761f57a6e0a7 (declared company)
accounts  ./.spool/dev.auth.sqlite
listening on http://127.0.0.1:7765
studio    http://127.0.0.1:7765/
mcp       http://127.0.0.1:7765/mcp
```

One server runs on a store at a time, so a second `spool dev` on the same project is refused:

{/* sample: fails */}

```sh
spool dev
```

```text title="Output"
error: the store ./.spool/dev.duckdb is open in another process (PID 6644), most likely a `spool dev` that is already running on this project
hint: one server runs on a store at a time: use the one that is running, or stop it with Ctrl-C and start this one again
```

So is one on another project while the first holds the port:

```sh
spool init ../other
```

{/* sample: fails */}

```sh
spool dev ../other
```

```text title="Output"
project   ../other
store     ../other/.spool/dev.duckdb
applied   5ae1625b488b3935122d8dd627fe575b388a5aa360378fa4407aad08baaed1e2 (rules only)
accounts  ../other/.spool/dev.auth.sqlite
error: cannot listen on 127.0.0.1:7765: something else is listening there, perhaps a `spool dev` on another project
hint: give this one another port by adding `--listen 127.0.0.1:7766` to the command, and point the commands that call it there with SPOOL_URL=http://127.0.0.1:7766
```

Ctrl-C stops it after the runs in progress finish. [`spool reset`](#spool-reset) empties its store.

## spool add

`spool add --source crm --type company '{"id":"c-1","name":"Acorn Tools"}' --json`

Stores one row and returns the record ID and its identity ID. The project’s SQL rules compare the record with existing identities. If several identities fit, the response gives the review item and the identity is null. Pass `-` to read the JSON object from standard input. Use `--replace` to send a new version of a row under an existing key.

## spool load

`spool load <file> [--source <name>] [--type <name>] [--delimiter <c>] [--batch <n>]`

Loads a CSV file into a source. `-` reads standard input, and `.tsv` or `.tab` files are tab-separated. `--source` defaults to the project's only source, then to the source the file is named after (`crm-1.csv` and `crm.csv` go to `crm`), then to the source that lists most of the file's columns. `--type` defaults to the only entity type that reads the source. Loading doesn't match. Rows already held are skipped, and a changed row under the same key becomes a new version.

```sh
spool load samples/crm-1.csv
```

```text title="Output"
loaded  6 rows into source `crm`, type `company`: 6 new
next: `spool match` places them in identities
```

## spool extract

`spool extract [<path>...] [--source <name>] [--extractor <name>] [--again]`

Stores each file as a document, then runs an extractor over every document it hasn't read. Folders are read recursively, skipping dotfiles. A named file's key is its name, and a file found in a folder is keyed by its path from that folder, so `spool extract documents` stores documents/dev/a.txt as `dev/a.txt`. With no path, it runs the extractor over stored documents. The source is picked the way `spool load` picks it, and `--extractor` defaults to the project's only one. `--again` rereads every document. A first run may download dependencies, such as the sample extractor's model. [Extraction](/docs/concepts/extraction) covers extractors in depth.

Documents are read in batches, and each batch is kept when it ends. A batch is sized to at most a fifth of the server's `--task-timeout`, capped at two minutes. On a terminal, a spinner shows the extractor's output while the first batch starts, then a progress bar shows documents read and time remaining. With several batches, the command prints a total on standard error, plus the startup time if the first batch was slow. A failure keeps earlier batches, and Ctrl-C cancels the current batch and keeps earlier ones. Run the same command again to read the rest; with `--again` it starts over.

Documents the extractor couldn't read are listed under `failed` with the reason, and the next run retries them. If a batch fails on every document, the command stops. The extractor's standard error is shown, indented, when its batch ends. Mentions no extractor finds any more are retracted and listed under `taken back`. See [When an extractor fails](/docs/concepts/extraction#when-an-extractor-fails).

```sh
spool extract samples/notes-1.txt
```

```text title="Output"
source     notes
read       1 document from samples/notes-1.txt
loaded     1 new, 0 already held, 0 new versions
extractor  companies
found      3 records in 1 document: 3 new, 0 already held

  company  Acorn Tools Ltd          notes:notes-1.txt[54-69]
  company  Larkfield Logistics Ltd  notes:notes-1.txt[119-142]
  company  Brightwater Foods Ltd    notes:notes-1.txt[179-200]
next: `spool match` places them in identities
```

## spool match

`spool match [--type <name>] [--rematch] [--strategy <name>]`

Matches every record no match has examined yet, waits, and prints the report. Each entity type gets its own run and report; `--type` matches one. A failed run doesn't stop the others, but the command then fails. `--rematch` re-examines every record against the current rules and suggests merges without making them. `--strategy` picks the judge: `rules` (the default) or one of the project's strategies, with `--type` if the project has several types.

```sh
spool match
```

```text title="Output"
run         5, type `company`
examined    9 records, 8 candidate pairs
judgements  7 match, 1 no_match
placed      9 records, 5 identities created
```

## spool recompute

`spool recompute [--type <name>] [--identity <id>] [--detail] [--limit <n>] [--offset <n>]`
`spool recompute --apply <plan> [--type <name>] [--reason <text>]`

Previews the identities you'd get by matching every record from scratch with the current rules, compared with the identities you have. It changes nothing. Every type is recomputed unless `--type` names one. You get a summary, then the ten largest changes. `--detail` lists all of them, and `--identity` breaks down one change record by record. The last line is a plan hash for `--apply`. Applying recomputes, refuses if the result no longer matches the plan, and commits one engine changeset per type. [Matching](/docs/concepts/matching#recompute) shows the output.


| `<list>` | Lists | With an ID |
| --- | --- | --- |
| `runs [<run>]` | The latest runs | One run and what it reported |
| `records [<record>]` | Records | One record with its payload and evidence |
| `attributes` | For each entity type and source, the attributes of the records | |
| `identities [<identity>]` | Identities | One identity with its records, constraints and history |
| `documents [<document>]` | Documents | One document with its text |
| `review [<item>]` | Review items | One item with its records |
| `drafts [<draft>]` | Drafts | One draft with the changeset it would commit |
| `log` | The changeset log | |

Name a record by its ID or as `<source>:<key>`, the latest version of that row. Name a record found in a document the way lists show it, `<source>:<document>[<start>-<end>]`.

| Option | Meaning | Applies to |
| --- | --- | --- |
| `--type <name>` | Only this entity type | runs, identities, records, attributes, review, drafts |
| `--status <status>` | Only this status | runs, review, drafts |
| `--kind <kind>` | Only runs of this kind: `load`, `extract`, `match`, `reconcile`, `retract` | runs |
| `--source <name>` | Only this source | records, attributes, documents |
| `--key <key>` | Only this key within its source | records, documents |
| `--document <id>` | Only the records found in this document | records |
| `--unassigned` | Only records that wait for an identity | records |
| `--all-versions` | Every version, the ones later loads replaced as well | records, documents |
| `--attributes` | A column for each attribute of the records | records |
| `--ids` | List each record's ID as well | records |
| `--sort <column>` | List identities by `records`, `names`, `sources`, `label`, `entity_type`, `created` or `id` | identities |
| `--order <order>` | `asc` or `desc`, with `--sort` (default `asc`) | identities |
| `--after <id>` | Continue a list after this ID, or the log after this position, in the order of the list | identities, records, documents, review, log |
| `--limit <n>` | List at most this many | runs, identities, records, documents, review, log |

Each list takes only the options that apply to it, and none apply when you pass an ID. `spool show <list> -h` lists them.

Record and document lists show current versions only: each row as its source last sent it, and each mention as the latest version of its document has it. `--all-versions` adds the replaced versions, with a column marking the current one.

Each identity has three numbers that flag a wrong merge without any labelled data:

- **members**: the record count. Wrong merges snowball, so look at the largest identities first.
- **names**: distinct labels, ignoring case. One thing goes by a few names. Dozens means many things.
- **unlinked pairs**: the share of record pairs no link joins directly. A link is a `match` from a finished run, a `must_link`, or one record being a later version of the other. An unlinked pair is together only through a chain: A matches B and B matches C, so A and C share an identity with no rule between them. Mostly chains means rules that each hold have joined things that aren't one.

`--sort records --order desc` lists the largest identities first, and `--sort names --order desc` those with the most names. The JSON has `members`, `names`, `linked_pairs` and `unlinked_pairs`. [`spool explain <identity>`](#spool-explain) shows which rule joined the parts.

## spool explain

Shows where each record is and what placed it there, what each run that compared them concluded, the constraints and review items that name them, and what the current rules say about the pair.

## spool retract

`spool retract --source <name> --type <name> [<key>...] [--keys <file>] [--reason <text>]`

Retracts rows a source no longer holds, by key. `--keys` reads one key per line from a file, or from standard input with `-`. Every version stays in the store, leaves its identity in a changeset, and is ignored by later runs. The identity keeps its ID and other records. Loading the same key again restores every version. Unknown keys change nothing.

```sh
spool retract --source crm --type company c-6 --reason "deleted in the CRM"
```

```text title="Output"
run 7: 1 key named, 1 record taken back
1 record left an identity, by the changeset at log position 2
```

## spool reset

`spool reset [<dir>] [--store <path>] [--yes]`

Empties the development store so the next `spool dev` starts fresh. It deletes the store under `.spool/`, with every row, document, identity, run and changeset, after listing what it will delete and keep. It keeps the project's files, `spool dev`'s accounts and tokens, the manifest from `spool build`, and anything else under `.spool/`, such as an extractor's cache.

It asks first. Without a terminal, as in a script, it needs `--yes`. It refuses while a `spool dev` has the store open:

{/* sample: fails */}

```sh
spool reset --yes
```

```text title="Output"
error: the store .spool/dev.duckdb is open in another process (PID 6644), most likely a `spool dev` on this project. Nothing was removed.
hint: stop it with Ctrl-C, then run `spool reset` again
```

With the server stopped, it goes ahead:

{/* sample: stop servers */}

```sh
spool reset --yes
```

```text title="Output"
This starts the development store of this project over.

removes
  .spool/dev.duckdb.wal
  .spool/dev.duckdb

keeps
  .spool/dev.auth.sqlite  the accounts and tokens of `spool dev`
  the project's files     everything outside .spool/

removed  .spool/dev.duckdb.wal
removed  .spool/dev.duckdb

The next `spool dev` starts with an empty store. `spool load` and `spool extract` fill it again.
```

`--store` names the store if you gave `spool dev` one. It must be a `.duckdb` file directly under `.spool/`, so `spool reset` can never touch a store that `spool serve` runs on.

It deletes at most three things, and only if DuckDB created them: the write-ahead log `<store>.wal`, the spill directory `<store>.tmp` (symlinks inside it are removed, not followed), and finally the store file. If any of them, or `.spool` itself, is a symlink or an unexpected file type, it deletes nothing.

## spool update

`spool update [<dir>]`

Checks for the latest stable GitHub release and upgrades Spool if you installed it with `install.sh`. The installer verifies the archive and starts the new binary before switching the installation to it. For a manual installation or a container, upgrade using the same method you installed it with.

If you run it at a project's root or give its directory, the installed binary runs `spool update-skills` for that project, even when Spool is already current. Edited skills are kept. Restart any running Spool servers to use the new version.

## spool update-skills

`spool update-skills [<dir>] [--force]`

Updates the coding-agent files `spool init` wrote to match the installed `spool`: the skills in `.agents/skills/`, their symlinks in `.claude/skills/`, Spool's section of `AGENTS.md`, and a `CLAUDE.md` if there isn't one. Use [`spool update`](#spool-update) to upgrade a script installation and refresh its project skills together.

Files you've edited since Spool wrote them are kept and listed, and `--force` replaces them too. Spool's section of `AGENTS.md` sits between two marker lines, and the rest of the file is never touched. [Coding agents](/docs/agents) explains how edits are detected.

```sh
spool update-skills
```

## spool build

`spool build [<dir>] [--base-image <image>] [--install]`

Checks the project and compiles it into `.spool/manifest.json` for `spool serve`. It writes a Dockerfile if the project has none. `--install` starts each strategy and extractor once so `uv` and `bun` install their dependencies, including any model loaded at startup.

## spool apply

`spool apply [<dir>] --store <path> [--manifest <path>]`

Applies a manifest to a store: declares new entity types and rebuilds the feature table of each type whose declaration changed. Identities aren't touched. Stop the server first. The store is created if it doesn't exist.

## spool serve

`spool serve [--manifest <path>] [--store <path>] [--listen <addr>] [--public-url <url>] [--project <dir>] [--no-studio] [--plain-http] [--task-timeout <s>] [--tasks <dir>]`

Runs the production server. It listens on `0.0.0.0:7765`, and every caller is a signed-in person or a program with a token. [Deploying](/docs/deploying) walks through it.

## spool token

`spool token add <name> --store <path>`, `spool token list --store <path>`, `spool token revoke <name> --store <path>`

Creates, lists and revokes a server's tokens on the server's machine, whether or not the server is running. `add` prints the token once and nothing else. Callers send it as `Authorization: Bearer <token>`, and their changes are recorded as `agent:<name>`.

## spool schema

`spool schema`

Prints the JSON Schema of every value the API takes and returns.

## spool bench

`spool bench <scenario> [--db <path>] [--seed <n>] [--out <path>] [--list <n>] [--strategy <name>] [--task-timeout <s>] [--tasks <dir>]`

Runs a benchmark scenario: loads each step's files, matches, and scores the identities against the scenario's ground truth. Scenarios with documents are also scored on extraction, and on extraction and matching end to end. The [benchmarks](https://github.com/alexpatow/spool/tree/main/benchmarks) README describes each scenario.

## spool completions

`spool completions <shell>`

Prints a completion script for `bash`, `zsh`, `fish`, `powershell` or `elvish`. The install script links the bash, zsh and fish scripts where those shells look, and for zsh says what to add to `~/.zshrc`. To put one somewhere else:

{/* sample: skip writes into the reader's home directory */}

```sh
spool completions fish > ~/.config/fish/completions/spool.fish
```

## Environment

| --- | --- |
| `SPOOL_URL` | The server that client commands call |

| `SPOOL_PUBLIC_URL` | The address people reach `spool serve` by |
