---
title: Entity types and features
description: An entity type is a directory that says what its records are compared by, and how each source's columns become those features.
---

An **entity type** is a kind of thing you want one ID for: a company, a person, a product. Spool ships none. A project declares its own, and two projects need not agree on what a company looks like.

A **feature** is a value that records of that type are compared by. Sources name their columns differently and write values differently, so rules never read raw rows. They read features, which every source is mapped onto.

This page adds a second source to the sample project, with features of its own, and shows what happens to identities when a declaration changes.

## Before you start

The examples use the sample project with both of its files of rows loaded and matched, which is where [Getting started](/docs/getting-started) ends. If you have that project and its server is running, use it. If not, this makes it:

{/* sample: new session */}

```sh
spool init companies --example companies
cd companies
```

{/* sample: background */}

```sh
spool dev
```

Leave that running. In a second terminal, in the `companies` directory:

```sh
spool load samples/crm-1.csv
spool match
spool load samples/crm-2.csv
spool match
```

## An entity type is a directory

`entities/company/` declares the entity type `company`. This is the `entity.yaml` that `spool init --example companies` wrote:

{/* sample: existing */}

```yaml title="entities/company/entity.yaml"
# `features` is what records are compared by, and `label` is the feature a
# record is called by. `mapping` says, for each source, which column each
# feature comes from, and the transform it goes through if it needs one. A
# record found in a note has no country.
label: name
features: [name, name_key, country]

mapping:
  crm:
    name: name
    name_key: { from: name, transform: name_key }
    country: country
  notes:
    name: name
    name_key: { from: name, transform: name_key }
```

- **`features`**: the columns of the type's feature table, which is what rules read.
- **`label`**: the feature a record is called by when it is shown to a person.
- **`mapping`**: for each source, where each feature comes from.

The steps below add a company registry as a second source, and two features: `domain`, from a website, and `founded`, a date.

## Add transforms

A transform is a file under `transforms/`, named for the transform. It holds `lambda`, the names of its arguments, and one DuckDB expression over them:

```sql title="transforms/domain_of.sql"
-- "https://www.acorn.example/about" becomes "acorn.example".
lambda website: nullif(regexp_extract(lower(website), '^(?:https?://)?(?:www\.)?([^/:?#]+)', 1), '')
```

```sql title="transforms/founded_date.sql"
-- A date, or nothing when the text is not one.
lambda founded: try_cast(founded AS DATE)
```

A transform sees only the values it is given from one record. It cannot read a table. Every value reaches it as text, whatever type the row had. What it returns is the feature's type: `domain_of` gives text and `founded_date` gives a date, which a rule can then compare as a date.

## Add a source, and a column

```yaml title="sources/registry.yaml"
key: number
columns: [number, legal_name, country, founded]
```

```yaml title="sources/crm.yaml"
key: id
columns: [id, name, country, website]
```

## Map both sources

```yaml title="entities/company/entity.yaml"
label: name
features: [name, name_key, country, domain, founded]

mapping:
  crm:
    name: name
    name_key: { from: name, transform: name_key }
    country: country
    domain: { from: website, transform: domain_of }
  notes:
    name: name
    name_key: { from: name, transform: name_key }
  registry:
    name: legal_name
    name_key: { from: legal_name, transform: name_key }
    country: { from: country, transform: upper }
    founded: { from: founded, transform: founded_date }
```

How to read a mapping:

- `name: name` takes the column as it is.
- `{ from: website, transform: domain_of }` passes the column through a transform. `from` can be a list of columns for a transform with several arguments.
- A transform with no file in `transforms/` is the DuckDB function of that name. `upper` is one.
- A feature that a source does not map is empty for that source's records. The registry has no website, so its records have no `domain`. Every feature has to be mapped by at least one source.

## What changing a declaration does

When `entity.yaml` or a transform it uses changes, the feature table is computed again from the stored rows. `spool dev` printed `rebuilt company` when it did so. That is possible because records keep their rows as they arrived.

It changes no identity. Identities refer to records, not to features, so every ID stays where it was. Records that were already placed are also not matched again. [Matching](/docs/concepts/matching#rules-that-get-better) says what to do when a better feature would have matched differently.

## What is checked

A mistake in these files is found when the project is read, not when rows arrive. `spool info`, `spool build` and `spool dev` all refuse:

- a mapping that names a source with no file,
- a column the source does not list,
- a transform given the wrong number of columns,
- a transform or rule that DuckDB cannot prepare.

For example, with `legal_name` misspelt as `legal_nmae` in the mapping of `name`:

```yaml title="entities/company/entity.yaml"
label: name
features: [name, name_key, country, domain, founded]

mapping:
  crm:
    name: name
    name_key: { from: name, transform: name_key }
    country: country
    domain: { from: website, transform: domain_of }
  notes:
    name: name
    name_key: { from: name, transform: name_key }
  registry:
    name: legal_nmae
    name_key: { from: legal_name, transform: name_key }
    country: { from: country, transform: upper }
    founded: { from: founded, transform: founded_date }
```

{/* sample: fails */}

```sh
spool info
```

```text title="Output"
spool: ./entities/company/entity.yaml: mapping of `name` from `registry`: `legal_nmae` is not a column of sources/registry.yaml
```

`spool dev` says the same when the file is saved, and keeps running the last version that worked. Put the name right again:

```yaml title="entities/company/entity.yaml"
label: name
features: [name, name_key, country, domain, founded]

mapping:
  crm:
    name: name
    name_key: { from: name, transform: name_key }
    country: country
    domain: { from: website, transform: domain_of }
  notes:
    name: name
    name_key: { from: name, transform: name_key }
  registry:
    name: legal_name
    name_key: { from: legal_name, transform: name_key }
    country: { from: country, transform: upper }
    founded: { from: founded, transform: founded_date }
```

## Names

The names of sources, entity types, transforms and rules come from file and directory names. Use lowercase letters, digits and underscores, starting with a letter: that is accepted for every kind of name. An entity type's name may have 48 characters at most.

## What a declaration cannot do

- A feature is computed by a SQL expression, not by your own code. A normaliser that needs a lookup table or a library has to run before the rows are sent.
- An entity type cannot be declared through the API. It is a change to the project, which `spool dev` applies as you save and [`spool build` and `spool apply`](/docs/deploying) apply to a deployed server.
- Rules compare records of one entity type. Nothing matches a company against a person.
