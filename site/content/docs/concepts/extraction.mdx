title: Extraction
description: Records out of text. A document is stored, an extractor finds where it names a thing, and each place becomes a record. With the sample extractor, which asks a small model, and with your own code in Python or TypeScript.
---

Rows are one way records get into Spool. The other is text.

- A **document** is a text, stored as it arrived: a call note, an article, an email.
- An **extractor** reads documents and reports each place where one names a thing of an entity type. A place is a **mention**: the document, where it starts and ends, and the attributes the extractor read off it, such as a name.
- Each mention becomes a **record**. From there it is matched, placed in an identity, explained and corrected like a record that came from a row.

An extractor is a Python file or a TypeScript file: code that the server runs as a child process. The one `spool init --example companies` writes asks a small model that runs on your machine and is fetched on the extractor's first run. [An extractor that asks a hosted model](#with-a-hosted-model) is your code, with your key.

## What the project needs

A source for the documents. Its columns are the attributes an extractor may give a mention:

{/* sample: existing */}

```yaml title="sources/notes.yaml"
# A source of documents: here, notes of calls. An extractor finds records in
# them, and `columns` is everything such a record may say.
columns: [name]
```

A mapping from those attributes to the entity type's features, beside the mapping of the rows:

{/* sample: existing */}

```yaml title="entities/company/entity.yaml"
# `features` is what records are compared by, and `label` is the feature a
# record is called by. `mapping` says, for each source, which column each
# feature comes from, and the transform it goes through if it needs one. A
# record found in a note has no country.
label: name
features: [name, name_key, country]

mapping:
  crm:
    name: name
    name_key: { from: name, transform: name_key }
    country: country
  notes:
    name: name
    name_key: { from: name, transform: name_key }
```

A note says nothing about a country, so a record from one has none. The rule that keeps different countries apart does not hold against it.

And an extractor, under `extractors/`. `spool init --example companies` writes all three.

## The sample extractor

{/* sample: existing */}

```python title="extractors/companies.py"
# /// script
# requires-python = ">=3.10,<3.13"
# dependencies = ["fast-gliner>=0.4.1,<0.5"]
# ///
"""Finds the companies a document names, with a small model that runs here.

An extractor reads documents and says where they name something, and each
thing it finds becomes a record. Spool runs this file with `uv`, which
installs what the lines above list. The first run fetches about 330 MB, most
of it the model, and later runs fetch nothing. No document leaves this
machine and there is no key to set.
"""

import sys

from fast_gliner import FastGLiNER
from spool import extractor

# What to look for. On the left is the word the model is given, and the word
# decides what is found: "company" misses most universities, parties and
# charities, and "organization" finds them. Any word will do, "person" or
# "medicine" as well. On the right is the entity type of this project that
# such a find becomes a record of.
LOOK_FOR = {"company": "company"}

# GLiNER small: 245 MB, Apache-2.0, at the version it was tried with.
MODEL = "onnx-community/gliner_small-v2.1"
WEIGHTS = "onnx/model_q4f16.onnx"
VERSION = "8142fb00740ccea973e64b1272949ff48653df5e"


def load():
    """The model: read from this machine if it is here, and fetched if not."""
    files = {"onnx_path": WEIGHTS, "allow_patterns": ["*.json", WEIGHTS], "revision": VERSION}
    try:
        return FastGLiNER.from_pretrained(MODEL, local_files_only=True, **files)
    except FileNotFoundError:
        print(f"Fetching the model {MODEL} (245 MB), once.", file=sys.stderr)
        return FastGLiNER.from_pretrained(MODEL, **files)


# Loaded as the file starts, so that `spool build --install` fetches it too.
model = load()


@extractor
def find(document):
    # The model reads 384 words at a time and ignores the rest, so a long
    # document is read in pieces.
    for piece in document.pieces(300):
        for found in model.predict_entities(piece.text, list(LOOK_FOR)):
            # The model counts in bytes, and Spool in characters.
            start = len(piece.text.encode()[: found["start"]].decode())
            end = start + len(found["text"])
            # `name` is a column of sources/notes.yaml.
            yield piece.mention(LOOK_FOR[found["label"]], start, end, name=found["text"])
```

The server runs a `.py` file with [uv](https://docs.astral.sh/uv/), which has to be installed where the server runs. `uv` installs what the first lines of the file list. The first run fetches about 330 MB, most of it the model, and later runs fetch nothing.

- `@extractor` marks the function the server calls, once for each document.
- `document.pieces(300)` gives the text in pieces of at most 300 words, because the model reads only so much at once.
- `LOOK_FOR` holds the word the model is given, "company", and the entity type a find becomes a record of.
- `piece.mention(entity_type, start, end, **attributes)` is one mention, with `start` and `end` counted within the piece. An attribute the source does not list is refused.

## Your own code, in Python

An extractor of your own is another file in `extractors/`. This one reads a second note:

```text title="notes-2.txt"
Dana called again. Acorn Tools are moving their account to Kestrel Analytics
next quarter, and Larkfield will keep the deliveries.
```

This file has the shape of an extractor that asks a hosted language model. `ask` stands where the model's answer goes: here it gives two names from a fixed list, so that the example runs with no key.

```py title="extractors/names.py"
"""Finds the companies a note names, by asking for them and locating each answer in the text."""

from spool import extractor

KNOWN = ["Acorn Tools", "Kestrel Analytics"]


def ask(text):
    """The names in `text`. A real extractor sends the text to a model here."""
    return [name for name in KNOWN if name in text]


@extractor
def find(document):
    for quote in ask(document.text):
        for start, end in document.find(quote):
            yield document.mention("company", start, end, name=quote)
```

- `document.text` is the text, and `document.key` its key.
- `document.find(quote)` gives each place the quote is in the text. Ask a model for quotes and not for positions: models count characters badly.
- `document.mention(entity_type, start, end, **attributes)` is one mention, with `start` and `end` counted within the whole text.

### With a hosted model

This extractor asks OpenAI's chat-completions API, or any API that speaks it, for the companies a document names. It uses only Python's standard library, so `uv` installs nothing for it, and it asks for structured output, so the answer is JSON of a fixed shape.

It tells the model what a company is from a file of the project, `entities/company/extract.md`. Each entity type may have one:

```md title="entities/company/extract.md"
A company is a business the text names: a legal entity such as a corporation,
a limited company or a partnership.

Quote the name exactly as the text writes it, with its legal form if the text
gives one. A product, a person, a place or a public body is not a company.

Attributes:

- `name`: the name as quoted.
```

```py title="extractors/llm.py"
"""Finds the companies a document names, by asking a hosted model.

It reads these from its environment, which the project's .env adds to:

    OPENAI_API_KEY   the key
    OPENAI_MODEL     the model, one that supports structured output
    OPENAI_BASE_URL  optional: another API that speaks the same protocol
"""

import json
import os
import sys
import urllib.request

from spool import extractor

KEY = os.environ.get("OPENAI_API_KEY")
MODEL = os.environ.get("OPENAI_MODEL")
URL = os.environ.get("OPENAI_BASE_URL", "https://api.openai.com/v1") + "/chat/completions"

# Structured output: the model answers with this shape and nothing else.
SCHEMA = {
    "type": "object",
    "properties": {"names": {"type": "array", "items": {"type": "string"}}},
    "required": ["names"],
    "additionalProperties": False,
}


def ask(instructions, text):
    """The names the model quotes from `text`."""
    request = urllib.request.Request(
        URL,
        headers={"Authorization": f"Bearer {KEY}", "Content-Type": "application/json"},
        data=json.dumps({
            "model": MODEL,
            "messages": [
                {"role": "system", "content": instructions},
                {"role": "user", "content": text},
            ],
            "response_format": {
                "type": "json_schema",
                "json_schema": {"name": "companies", "strict": True, "schema": SCHEMA},
            },
        }).encode(),
    )
    with urllib.request.urlopen(request, timeout=60) as response:
        answer = json.load(response)
    return json.loads(answer["choices"][0]["message"]["content"])["names"]


@extractor
def find(document, task):
    if not KEY or not MODEL:
        raise SystemExit("set OPENAI_API_KEY and OPENAI_MODEL in the project's .env")
    try:
        names = ask(task.instructions("company") or "List the companies.", document.text)
    except Exception as error:
        # A wrong key or model fails every document alike: stop the run.
        if getattr(error, "code", None) in (401, 403, 404):
            raise
        # Anything else costs this document only, and the run goes on.
        print(f"skipped {document.key}: {error}", file=sys.stderr)
        return
    for name in set(names):
        for start, end in document.find(name):
            yield document.mention("company", start, end, name=name)
```

- The key and the model go in the project's `.env`, which Git ignores: copy `.env.example` to `.env` and set `OPENAI_API_KEY=...` and `OPENAI_MODEL=...` there. Spool reads it each time it starts the extractor, so a change needs no restart, and never prints a value. A variable set in the terminal that started the server wins over `.env`. [Project structure](/docs/project-structure#secrets) has the rules of the file.
- `find` asks for `document` and `task`. `task.instructions("company")` is the text of `extract.md`.
- The `try` is what keeps one bad answer from losing the run: an exception that leaves the extractor fails the whole run and keeps nothing. [When an extractor fails](#when-an-extractor-fails) says what a skipped document costs.
- The model gives quotes, and `document.find` places each one. A quote the text does not have, letter for letter, is found nowhere and dropped.

The repository's [`llm.py`](https://github.com/alexpatow/spool/blob/main/benchmarks/extraction/company-news/extractors/llm.py) does the same for every entity type the project declares, with attributes, and gives a place to the longest of two overlapping quotes. No test in the repository calls a hosted model. An extractor that calls a model costs what the model costs, for every document, and the server stops one that runs longer than `--task-timeout`, which is 600 seconds unless set.

### Every document at once

An extractor's function asks for what it needs by the names of its parameters:

- `document`: it is called once for each document. A run that takes long writes a line such as `read 400 of 3,053 documents` to standard error every ten seconds.
- `documents`: it is called once, with every document of the run as a list.
- `task`: with either of the two, for what the run knows besides the documents.

Either form returns its mentions as a list or yields them, and a `None` among them is dropped. `task` offers:

| | |
| --- | --- |
| `task.documents` | The documents of the run. Each has `text`, `key`, `source`, `id` (of this version) and `uri` |
| `task.entity_types` | The names of the project's entity types |
| `task.instructions(type)` | The text of the type's `extract.md`, or `None` |
| `task.features(type)` | The type's features, as `{"name": ..., "data_type": ...}` |
| `task.run`, `task.extractor` | The run's number and the extractor's name |

Take `documents` when the documents are better handled together: to send requests to a model side by side, to put several documents in one request, or to keep something from one document to the next. Take `@extractor` off `find` above and add this, which reads eight documents at a time:

```py
from concurrent.futures import ThreadPoolExecutor


@extractor
def find_all(documents, task):
    with ThreadPoolExecutor(max_workers=8) as pool:
        for mentions in pool.map(lambda document: list(find(document, task)), documents):
            yield from mentions
```

## In TypeScript

The same extractor as a `.ts` file, which the server runs with [Bun](https://bun.sh):

import { extractor } from "spool-strategy";

const KNOWN = ["Acorn Tools", "Kestrel Analytics"];

await extractor(async (task) => {
  const documents = await task.documents();
  return documents.flatMap((document) =>
    KNOWN.flatMap((name) =>
      document.find(name).map(([start, end]) => document.mention("company", start, end, { name })),
    ),
  );
});

## What an extractor's process gets

The server starts the file as a child process for each run, and waits for it.

- **Working directory**: the project directory, so a relative path is relative to it.
- **Environment**: the server's own, with what the project's `.env` sets for variables the server's does not, without `SPOOL_TOKEN` and `SPOOL_GOOGLE_CLIENT_SECRET` whatever `.env` says, and with `SPOOL_TASK_DIR`, the directory of the run's files. Without `SPOOL_TASK_DIR`, `@extractor` does nothing, so the file can be imported and its function called in a test.
- **Input and output**: no standard input. Standard output is shown nowhere. Standard error is shown to whoever waits for a run that takes more than a few seconds, and its last 20 lines are in the error of a run that fails. Of a run that ends sooner and succeeds, nothing it wrote is shown or kept.
- **Its files**: the documents and what the extractor writes are Parquet files in `SPOOL_TASK_DIR`, under `spool-tasks` in the system's temporary directory unless the server was started with `--tasks`. A run that fails leaves them there, with `stderr.log`, and its error names the directory. `spool` and `spool-strategy` hide them.

A `.py` file runs as `uv run --with pyarrow --script <file>`:

- `uv` reads the block of comments that begins `# /// script`, as in the sample extractor. It installs `dependencies` into an environment of the file's own, once, and fetches a Python that `requires-python` allows if none on the machine does.
- With no `requires-python`, `uv` takes a Python already on the machine, one it installed itself before the system's, and fetches one only when it finds none. Name a version, or set `UV_PYTHON_PREFERENCE=only-managed` where the server starts, to keep the system's Python out.
- A file with no such block runs in an environment of its own that holds only pyarrow, so the packages of the system's Python are not there.
- pyarrow is always added, because the `spool` module reads and writes Parquet with it. `spool` itself comes from the server and is not a package to list.
- The directory of the file is not on Python's import path, so `import helpers` does not find `extractors/helpers.py`. An extractor is one file.

A `.ts` file runs as `bun run <file>`, and finds `spool-strategy` through `NODE_PATH`, which the server sets.

## When an extractor fails

A run keeps everything or nothing. One exception that leaves the extractor, an exit status other than 0, a run stopped for taking too long, or one mention the server refuses, such as one with an attribute its source does not list, fails the whole run. No mention is stored, and no document counts as read, not even those read before the failure, so the next run reads every one of them again, and an extractor that calls a model pays for them again.

An extractor that calls a model therefore catches errors for each document, as `llm.py` above does: it lets through only what would fail every document alike, and skips the document otherwise. A skipped document counts as read, with 0 mentions, the same as a document that names nothing, and nothing marks it to be read again. Sending the same file again adds nothing, and `--again` reads every document again. The line `llm.py` writes for a skipped document is on standard error, so in a run that ends within a few seconds nobody sees it.

## Over HTTP and MCP

| | Store a document | Run an extractor |

| Command | `spool extract <file>` does both | `spool extract` with no file |
| HTTP | `POST /v1/documents` | `POST /v1/extractions` |

[Getting started](/docs/getting-started#extract-records-from-text) has a call of each. `POST /v1/extractions` takes `extractor`, `source` to keep to the documents of one source, `again` to read every document again, and `limit`.

## How good is it

An extractor is scored apart from matching. `spool bench` runs a scenario with labelled mentions and reports what the extractor found, missed and made up. The repository's [`benchmarks/extraction/company-news`](https://github.com/alexpatow/spool/tree/main/benchmarks/extraction/company-news) has ten news items, a rule-based extractor in both languages, and its scores.

It also reports the two together, end to end: the identities against the true entities over every labelled mention, where a mention the extractor missed is with nothing. [`benchmarks/extraction/linked-docred`](https://github.com/alexpatow/spool/tree/main/benchmarks#from-text-to-identities) measures all three on Linked-DocRED: the openings of 5,051 Wikipedia articles, with every mention labelled and linked to its Wikidata entry.

The benchmark is in the repository and not in the release. The dataset is in neither, because its licence is the GPL: the benchmark's script downloads it, 45 MB, from [alteca/Linked-DocRED](https://github.com/alteca/Linked-DocRED). It needs a clone, `uv` and a `spool`, and runs the installed one with `--spool`:

{/* sample: skip needs a clone of the repository, and downloads the dataset */}

```sh
git clone https://github.com/alexpatow/spool
cd spool
uv run benchmarks/extraction/linked-docred/run.py --spool "$(command -v spool)"
```

It writes each article as a text file under `benchmarks/.cache/linked-docred/documents/`, which is also where to take them from to try an extractor of your own, scores two extractors that need no model, and prints the reports. `--documents 200` takes the first 200 articles of each of the dataset's three files.

## What extraction does not do

- **Documents are text.** Spool does not read PDF or HTML. Turn them into text first.
- **The sample model finds what its word asks for.** Given "company", it misses most universities, parties and charities.
- **No model is in the binary.** The sample extractor fetches its model on its first run. Every extractor is a Python or TypeScript file, and needs `uv` or `bun` where the server runs.
- **A mention is a place.** Two mentions of one company in one document are two records, in one identity.
- **A changed extractor does not read again by itself.** `--again` has it read every document again.
- **Reading again takes nothing back.** The mentions a changed extractor no longer finds stay, beside what it finds now. A mention it finds again unchanged keeps the version of the extractor that first found it, so no record tells a stale mention from a current one.
- **A run keeps everything or nothing.** [When an extractor fails](#when-an-extractor-fails) has the pattern that keeps one bad document from losing the rest.
- **A document is one request.** A file larger than the API's limit of 256 MiB cannot be stored.
