Records come from rows or from text. This page is about text.

- A **document** is text, stored as it arrived: a call note, an article, an email.
- An **extractor** reads documents and reports each place that names something of an entity type. Each place is a **mention**: the document, its start and end, and attributes the extractor read, such as a name.
- Each mention becomes a **record**. From there it's matched, placed, explained and corrected like any row.

An extractor is a Python or TypeScript file the server runs as a child process. The one `spool init --example companies` writes uses a small local model, downloaded on first run. [Calling a hosted model](#with-a-hosted-model) is your code with your key.

## What the project needs

A source for the documents. Its columns are the attributes an extractor can give a mention:

{/* sample: existing */}

```yaml title="sources/notes.yaml"
# A source of documents: here, notes of calls. An extractor finds records in
# them, and `columns` is everything such a record may say.
columns: [name]
```

A mapping from those attributes to the entity type's features, next to the rows' mapping:

{/* sample: existing */}

```yaml title="entities/company/entity.yaml"
# `features` is what records are compared by, and `label` is the feature a
# record is called by. `mapping` says, for each source, which column each
# feature comes from, and the transform it goes through if it needs one. A
# record found in a note has no country.
label: name
features: [name, name_key, country]

mapping:
  crm:
    name: name
    name_key: { from: name, transform: name_key }
    country: country
  notes:
    name: name
    name_key: { from: name, transform: name_key }
```

Notes don't mention a country, so their records have none, and the country rule doesn't apply to them.

And an extractor, under `extractors/`. `spool init --example companies` writes all three.

## The sample extractor

{/* sample: existing */}

```python title="extractors/companies.py"
# /// script
# requires-python = ">=3.10,<3.13"
# dependencies = ["fast-gliner>=0.4.1,<0.5"]
# ///
"""Finds the companies a document names, with a small model that runs here.

An extractor reads documents and says where they name something, and each
thing it finds becomes a record. Spool runs this file with `uv`, which
installs what the lines above list. The first run fetches about 330 MB, most
of it the model, and later runs fetch nothing. No document leaves this
machine and there is no key to set.
"""

import sys

from fast_gliner import FastGLiNER
from spool import extractor

# What to look for. On the left is the word the model is given, and the word
# decides what is found: "company" misses most universities, parties and
# charities, and "organization" finds them. Any word will do, "person" or
# "medicine" as well. On the right is the entity type of this project that
# such a find becomes a record of.
LOOK_FOR = {"company": "company"}

# GLiNER small: 245 MB, Apache-2.0, at the version it was tried with.
MODEL = "onnx-community/gliner_small-v2.1"
WEIGHTS = "onnx/model_q4f16.onnx"
VERSION = "8142fb00740ccea973e64b1272949ff48653df5e"


def load():
    """The model: read from this machine if it is here, and fetched if not."""
    files = {"onnx_path": WEIGHTS, "allow_patterns": ["*.json", WEIGHTS], "revision": VERSION}
    try:
        return FastGLiNER.from_pretrained(MODEL, local_files_only=True, **files)
    except FileNotFoundError:
        print(f"Fetching the model {MODEL} (245 MB), once.", file=sys.stderr)
        return FastGLiNER.from_pretrained(MODEL, **files)


# Loaded as the file starts, so that `spool build --install` fetches it too.
model = load()


@extractor
def find(document):
    # The model reads 384 words at a time and ignores the rest, so a long
    # document is read in pieces.
    for piece in document.pieces(300):
        for found in model.predict_entities(piece.text, list(LOOK_FOR)):
            # The model counts in bytes, and Spool in characters.
            start = len(piece.text.encode()[: found["start"]].decode())
            end = start + len(found["text"])
            # `name` is a column of sources/notes.yaml.
            yield piece.mention(LOOK_FOR[found["label"]], start, end, name=found["text"])
```

The server runs `.py` files with [uv](https://docs.astral.sh/uv/), which installs the dependencies listed at the top of the file. The first run downloads about 330 MB, mostly the model.

- `@extractor` marks the function the server calls, once per document.
- `document.pieces(300)` splits the text into chunks of up to 300 words, because the model has a limited window.
- `LOOK_FOR` maps the word the model looks for, "company", to the entity type its finds become.
- `piece.mention(entity_type, start, end, **attributes)` is one mention, with offsets within the piece. Attributes the source doesn't list are rejected.

## Your own code, in Python

Your own extractor is another file in `extractors/`. This one reads a second note:

```text title="notes-2.txt"
Dana called again. Acorn Tools are moving their account to Kestrel Analytics
next quarter, and Larkfield will keep the deliveries.
```

This file has the shape of an extractor that calls a hosted LLM. `ask` stands in for the model call: here it returns names from a fixed list, so the example runs without a key.

```py title="extractors/names.py"
"""Finds the companies a note names, by asking for them and locating each answer in the text."""

from spool import extractor

KNOWN = ["Acorn Tools", "Kestrel Analytics"]


def ask(text):
    """The names in `text`. A real extractor sends the text to a model here."""
    return [name for name in KNOWN if name in text]


@extractor
def find(document):
    for quote in ask(document.text):
        for start, end in document.find(quote):
            yield document.mention("company", start, end, name=quote)
```

- `document.text` is the text, and `document.key` its key.
- `document.find(quote)` returns each place the quote appears. Ask models for quotes, not offsets: they count characters badly.
- `document.mention(entity_type, start, end, **attributes)` is one mention, with offsets within the whole text.

### With a hosted model

This extractor asks OpenAI's chat completions API, or any compatible API, for the companies a document names. It uses only Python's standard library, so `uv` installs nothing, and requests structured output, so the response is JSON of a fixed shape.

It tells the model what a company is from a project file, `entities/company/extract.md`. Each entity type can have one:

```md title="entities/company/extract.md"
A company is a business the text names: a legal entity such as a corporation,
a limited company or a partnership.

Quote the name exactly as the text writes it, with its legal form if the text
gives one. A product, a person, a place or a public body is not a company.

Attributes:

- `name`: the name as quoted.
```

```py title="extractors/llm.py"
"""Finds the companies a document names, by asking a hosted model.

It reads these from its environment, which the project's .env adds to:

    OPENAI_API_KEY   the key
    OPENAI_MODEL     the model, one that supports structured output
    OPENAI_BASE_URL  optional: another API that speaks the same protocol
"""

import json
import os
import urllib.request

from spool import extractor

KEY = os.environ.get("OPENAI_API_KEY")
MODEL = os.environ.get("OPENAI_MODEL")
URL = os.environ.get("OPENAI_BASE_URL", "https://api.openai.com/v1") + "/chat/completions"

# Structured output: the model answers with this shape and nothing else.
SCHEMA = {
    "type": "object",
    "properties": {"names": {"type": "array", "items": {"type": "string"}}},
    "required": ["names"],
    "additionalProperties": False,
}


def ask(instructions, text):
    """The names the model quotes from `text`."""
    request = urllib.request.Request(
        URL,
        headers={"Authorization": f"Bearer {KEY}", "Content-Type": "application/json"},
        data=json.dumps({
            "model": MODEL,
            "messages": [
                {"role": "system", "content": instructions},
                {"role": "user", "content": text},
            ],
            "response_format": {
                "type": "json_schema",
                "json_schema": {"name": "companies", "strict": True, "schema": SCHEMA},
            },
        }).encode(),
    )
    with urllib.request.urlopen(request, timeout=60) as response:
        answer = json.load(response)
    return json.loads(answer["choices"][0]["message"]["content"])["names"]


@extractor
def find(document, task):
    if not KEY or not MODEL:
        raise SystemExit("set OPENAI_API_KEY and OPENAI_MODEL in the project's .env")
    try:
        names = ask(task.instructions("company") or "List the companies.", document.text)
    except Exception as error:
        # Not read: the next extraction reads this document again.
        yield document.failed(f"the model's API: {error}")
        return
    for name in set(names):
        for start, end in document.find(name):
            yield document.mention("company", start, end, name=name)
```

- The key and model go in the project's `.env`, which Git ignores. Copy `.env.example` to `.env` and set `OPENAI_API_KEY=...` and `OPENAI_MODEL=...`. Spool rereads it each time the extractor starts, so changes need no restart, and it never prints a value. Variables set in the server's terminal win over `.env`. [Project structure](/docs/project-structure#secrets) covers the format.
- `find` takes `document` and `task`. `task.instructions("company")` is the text of `extract.md`.
- The `try` reports why a document failed. `document.failed(...)` discards its mentions, and the next extraction retries it. Without the `try`, the exception does the same with its own message. See [When an extractor fails](#when-an-extractor-fails).
- The model returns quotes, and `document.find` locates each one. A quote that isn't in the text verbatim is dropped.

The repository's [`llm.py`](https://github.com/alexpatow/spool/blob/main/benchmarks/extraction/company-news/extractors/llm.py) does the same for every entity type in the project, with attributes, and keeps the longer of two overlapping quotes. The server stops a run after `--task-timeout` (600 seconds by default), and `spool extract` sizes batches to a fifth of that, so long extractions don't need a longer limit.

### Every document at once

An extractor function declares what it needs by parameter name:

- `document`: called once per document. Long runs log progress like `read 400 of 3,053 documents` to standard error every ten seconds.
- `documents`: called once, with every document in the run as a list.
- `task`: alongside either, for run context beyond the documents.

Either form returns or yields mentions, and `None` values are dropped. `task` offers:

| | |
| --- | --- |
| `task.documents` | The run's documents. Each has `text`, `key`, `source`, `id` (of this version) and `uri` |
| `task.entity_types` | The project's entity type names |
| `task.instructions(type)` | The text of the type's `extract.md`, or `None` |
| `task.features(type)` | The type's features, as `{"name": ..., "data_type": ...}` |
| `task.run`, `task.extractor` | The run's number and the extractor's name |

Use `documents` when it's better to handle documents together: to call a model in parallel, batch several documents per request, or carry state between documents. Remove `@extractor` from `find` above and add this, which reads eight documents at a time:

```py
from concurrent.futures import ThreadPoolExecutor


@extractor
def find_all(documents, task):
    with ThreadPoolExecutor(max_workers=8) as pool:
        for mentions in pool.map(lambda document: list(find(document, task)), documents):
            yield from mentions
```

## What an extractor's process gets

The server starts the file as a child process for each run, and waits for it.

- **Working directory**: the project directory.
- **Environment**: the server's, plus variables from the project's `.env` that the server doesn't set, minus `SPOOL_TOKEN` and `SPOOL_GOOGLE_CLIENT_SECRET`, plus `SPOOL_TASK_DIR` for the run's files. Without `SPOOL_TASK_DIR`, `@extractor` does nothing, so you can import the file and call its function in a test.
- **Input and output**: no standard input, and standard output is discarded. Standard error goes to whoever runs `spool extract`: live during a slow first batch, then after each batch, minus anything already shown and the helper's own progress lines. `spool dev` and `spool serve` print it too, tagged with the extractor and run. A run's report keeps the last 100 lines as `stderr`, and a failed run's error includes the last 20.
- **Files**: documents and the extractor's output are Parquet files in `SPOOL_TASK_DIR`, under `spool-tasks` in the system temp directory unless the server was started with `--tasks`. A failed run leaves them there with `stderr.log`, and its error names the directory. The `spool` and `spool-strategy` helpers hide them.

A `.py` file runs as `uv run --with pyarrow --script <file>`:

- `uv` reads the `# /// script` comment block, as in the sample extractor. It installs `dependencies` into the file's own environment once, and downloads a Python that satisfies `requires-python` if none on the machine does.
- Without `requires-python`, `uv` prefers a Python it installed, then the system's, and downloads one only if it finds neither. Pin a version, or set `UV_PYTHON_PREFERENCE=only-managed` for the server, to keep the system Python out.
- A file without the block runs in its own environment with only pyarrow, isolated from system packages.
- pyarrow is always added, because the `spool` module uses it for Parquet. `spool` itself comes from the server, so don't list it.
- The file's directory isn't on Python's import path, so `import helpers` won't find `extractors/helpers.py`. An extractor is one file.

A `.ts` file runs as `bun run <file>` and finds `spool-strategy` through `NODE_PATH`, which the server sets.

## When an extractor fails

**One document fails alone.** Return or yield `document.failed(reason)` in place of a document's mentions, in Python or TypeScript, and the rest of the batch carries on. In Python, an exception escaping a per-document function does the same, with its message as the reason. A failed document isn't marked read and keeps none of its mentions. `spool extract` lists failures with reasons, `spool show documents` and the studio show `llm failed in run 12: the model's API: ...`, and the next run retries them along with unread documents. Within one command, a failed document isn't retried. If every document in a batch fails, which usually means a bad key or a missing model, the command stops.

**Some failures fail the batch.** An exception escaping a function that takes every document, a non-zero exit, a timeout, or a mention the server rejects (such as one with an undeclared attribute) fails the whole batch. Nothing from it is stored or marked read, so the next run reads those documents again, and a model-backed extractor pays for them again. Each batch is its own run, so earlier batches are kept, and the command reports how many documents they read. Run it again to continue.

Ctrl-C cancels the running batch: the server stops the extractor and its child processes, discards that batch, and the command reports what earlier batches kept. A second Ctrl-C exits without waiting. `POST /v1/runs/{run}/cancel` does the same for API clients.

While a run reads a document, `spool show documents` and the studio show it as in progress, with the run. Documents from a failed or cancelled run count as unread.

## Reading again

A changed extractor doesn't reread documents on its own. `--again` rereads every document. New findings are matched to stored mentions by position: a mention found again with the same attributes is the same record, and one with different attributes becomes a new version.

A mention that no extractor's latest reading finds any more is retracted, like a row its source dropped. It stays in the store and leaves its identity in a changeset recorded under whoever ran the extraction. The identity keeps its ID and other records, and an identity that loses its last record keeps its ID until a record joins again. Mentions another extractor still finds stay, because each extractor's latest reading counts. Mentions of entity types the project no longer declares, or no longer reads from that source, are left alone. `spool extract` reports how many it retracted, and `spool show records <record>` shows when a record was retracted. Finding the mention again restores it to the identity it left. If a reading finds nothing at all in documents that had mentions, which looks like a broken extractor, `spool extract` warns on standard error and says how to restore them.

Each record from a document lists the readings that found it, with the extractor version: `found by` in `spool show records <record>`, and `found_by` over HTTP. That's how you tell a mention only an old version found from one the current version finds.

## Over HTTP and MCP

| | Store a document | Run an extractor |
| --- | --- | --- |
| Command | `spool extract <path>` does both | `spool extract` with no path |
| HTTP | `POST /v1/documents` | `POST /v1/extractions` |
| MCP | `load_documents` | `run_extraction` |

[Getting started](/docs/getting-started#extract-records-from-text) shows each call. `POST /v1/extractions` takes `extractor`, `source` to limit it to one source, `again` to reread everything, and `limit`. The run reports in `left` how many documents remain, which is how `spool extract` batches: it calls again until none are left. Later batches pass `since` with the first batch's run, so no document is read twice and failures aren't retried immediately. The run also reports `failed` with reasons, `taken_back`, `retract_runs` and `stderr`.

## Measuring an extractor

Extraction is scored separately from matching. `spool bench` runs a scenario with labelled mentions and reports what the extractor found, missed and invented. [`benchmarks/extraction/company-news`](https://github.com/alexpatow/spool/tree/main/benchmarks/extraction/company-news) has ten news items, a rule-based extractor in both languages, and its scores.

It also scores extraction and resolution end to end: identities against the true entities over every labelled mention, counting a missed mention as unresolved. [`benchmarks/extraction/linked-docred`](https://github.com/alexpatow/spool/tree/main/benchmarks#from-text-to-identities) measures all three on Linked-DocRED: the openings of 5,051 Wikipedia articles, with every mention labelled and linked to Wikidata.

The benchmark lives in the repository. Its script downloads the GPL-licensed dataset, 45 MB, from [alteca/Linked-DocRED](https://github.com/alteca/Linked-DocRED). You need a clone, `uv` and a `spool` binary, passed with `--spool`:

{/* sample: skip needs a clone of the repository, and downloads the dataset */}

```sh
git clone https://github.com/alexpatow/spool
cd spool
uv run benchmarks/extraction/linked-docred/run.py --spool "$(command -v spool)"
```

It writes each article as a text file under `benchmarks/.cache/linked-docred/documents/`, scores two model-free extractors, and prints the reports. To try your own extractor on the same data, `spool extract benchmarks/.cache/linked-docred/documents` loads all 5,051 into your project in batches, and `spool match` resolves every entity type. `--documents 200` takes the first 200 articles from each of the dataset's three files.

## Good to know

- **Documents are plain text.** Convert PDF and HTML first.
- **The model finds what you ask for.** Given "company", the sample model skips most universities, parties and charities. Try "organization" for those.
- **A mention is a position.** Two mentions of one company in one document are two records in one identity.
- **Failed documents are retried on every run.** Each retry calls the model again.
- **Documents are capped at 256 MiB**, the API's request limit.
