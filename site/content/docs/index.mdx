Spool pulls records out of text and rows, decides which are the same real-world thing, and gives each thing an ID that stays the same as more arrive. Working out which records are the same thing is called entity resolution, or record linkage. Spool does that, takes records from text as well as from tables, and keeps the IDs.

New to these terms? [What the hell is Entity Extraction and Resolution?](/explained) shows each step on the sample data, in pictures.

## How the parts fit

Spool is one server. It is written in Rust and keeps its data in one file of [DuckDB](https://duckdb.org), a database that runs inside the server's process. It is driven by a project, which is a directory of YAML and SQL files that you keep in Git.

1. **A project is a directory.** Sources, features, rules and extractors are files, and a file's path is its name. [Project structure](/docs/project-structure)
2. **Records come from rows or from text.** A row of a source becomes a record. A document is stored, and an extractor finds the places where it names a thing: each place becomes a record. An extractor is code in Python or TypeScript, which the server runs as a child process. The one a new project has asks a small model that runs on your machine. A record is never changed, and loading it twice does nothing. [Records and sources](/docs/concepts/records-and-sources), [Extraction](/docs/concepts/extraction)
3. **Records are compared by features.** Each source's columns are mapped onto the features of an entity type, such as `company`, that you declare. [Entity types and features](/docs/concepts/entity-types-and-features)
4. **Rules judge pairs.** A match compares what is new with what is known and records a judgement for each pair: `match` or `no_match`. A rule is a SQL condition over two records. [Matching](/docs/concepts/matching)
5. **Judgements become identities.** New records join an identity or start one. A match never merges or splits identities that exist. Every change is an entry in a log, with an author and a reason, and can be undone. [Identities](/docs/concepts/identities)
6. **What cannot be decided waits.** A record that fits two identities, and an identity that may have come apart, are left for a person or an agent. [Review](/docs/concepts/review)
7. **Other systems store the ID.** They look it up by a row's source and key, and follow the log to learn of merges and splits. [Using the IDs](/docs/using-the-ids)

There are four ways in, and they reach the same server:

| | For | Page |
| --- | --- | --- |
| The command line | Loading, extracting, matching, showing and explaining | [Command line](/docs/cli) |
| The HTTP API | Everything. The other three call it | [HTTP API](/docs/api) |

## Who it is for

- You maintain a list of companies, people or products that several sources feed, and other systems refer to them by ID.
- Some of what you know about them is in text: notes, articles, emails.
- You want to read why two records were matched, and take a wrong match back without rebuilding everything.
- You want matching rules reviewed like code, in files, with a history.
- You have people or agents making corrections, and need every correction attributed and reversible.
- You have thousands to a few million records, and one machine is enough.

If that is not you, [Limits](/docs/limits) says what Spool is not meant for, and [Compared with other tools](/docs/compared) says what to use.

## Where it stands

Spool's first commit was on 14 November 2026. It is version 0.1.0, under the MIT licence, and formats and the API can still change.

Every command on these pages is run by a script, [`site/scripts/check-samples.ts`](https://github.com/alexpatow/spool/blob/main/site/scripts/check-samples.ts), against a build of the source, and the output shown is compared with what was printed. It is run by hand before a page changes. Where a page runs the sample extractor, the script puts a file that needs no model in its place, unless it is told to run the model, and what is printed is the same.

The source is at [github.com/alexpatow/spool](https://github.com/alexpatow/spool).
